# 智能体与技能通用模板

> **适用范围**: 所有智能体（Agent）与后续技能（Skill）的定义
> **定位**: L2 通用模板层——统一管理智能体定义格式、任务输入输出、子代理任务单、会话记录、任务规模识别等跨 Agent 复用的模板与规范。各 Agent 文件通过引用本文件避免重复。

---

## 1 三层结构

| 层级 | 内容 | 存放位置 |
|:----:|------|---------|
| L1 角色定义层 | 角色核心定义、行为守则、职责目标、工作流程 | 各 Agent 文件（.claude/agents/dsh-*.md） |
| **L2 通用模板层** | **任务输入输出、工具表、子代理任务单、会话记录、任务规模识别、评审报告** | **本文件** |
| L3 项目资料层 | 设计文档、ADR、上游 DSH 文档 | docs/ |

---

## 2 智能体定义模板

### 2.1 frontmatter 字段结构

```yaml
---
name: "dsh-{角色}"            # 必填，全局唯一，如 dsh-ta / dsh-fed / dsh-fsd / dsh-qa / dsh-devops / dsh-tasker
description: "一句话职责描述"   # 必填，≤ 50 字
mode: all                      # 必填
metadata:
  author: "dsh-workbench"
  version: "1.0.0"             # 语义化版本，与 common-definitions.md §9 体系版本对齐
---
```

### 2.2 正文章节骨架（标准结构）

```
# {角色中文名} (dsh-{角色})
## 智能体摘要
## 1 角色定义（你是谁 / 性格特点）
## 2 职责和目标（核心职责 / 工作目标）
## 3 行为守则（顶部引用 common-definitions.md §5 通用守则，下方 2-3 条角色特有守则）
## 4 项目上下文加载（dsh-workbench 上下文 + AGENTS.md）
## 5 工作流程（流程图 + 步骤详解）
## 6 必须遵守的规范（技术标准 / 允许做 / 禁止做）
## 7 输入与输出（输入方式 / 输出方式 / 输出规范）
## 8 工具和能力（内置工具 / 核心能力）
## 9 交互与协作模式（与人类协作 / 与其他智能体协作，参照 common-definitions.md §4）
## 10 会话记录规范（.sessions/dsh-{角色}/{YYYY-MM-DD}/{task}.md）
## 11 任务规模识别（引用本文件 §7）
## 12 其他关注点
```

> 各 Agent 文件遵循上述骨架；确有角色差异时可增删小节，但 1/3/5/6/9/10/11 节不可省略。

## 3 任务输入格式

Agent 接收任务时应要求以下结构化输入（由 dsh-tasker 或用户提供）：

```yaml
任务输入:
  task_id: "TASK-YYYYMMDD-NNN"     # 任务 ID，tasker 统一分配
  task_name: "{任务名称}"
  task_type: "{设计/编码/测试/评审/发布/编排}"
  issue_link: "{GitHub issue 链接（如有）}"
  upstream_docs:                    # 上游文档引用
    - path: "{文档相对路径}"
  constraints:
    deadline: "{YYYY-MM-DD}"
  expected_output:
    deliverables:
      - path: "{产出路径}"
        format: "{markdown|code|json}"
    quality_gates: ["lint", "typecheck", "test", "build"]
  related_decisions:
    - "{已确认的技术决策}"
```

## 4 输出质量要求

### 4.1 文档类输出

| 维度 | 要求 | 检查方法 |
|------|------|----------|
| 结构完整性 | 必填章节无遗漏、必填字段无空缺 | 对照元数据规范与设计文档模板 |
| 置信度标注 | AI 拟定的事实性内容按三色标标注 | 见 `_common/confidence-marking.md` |
| 引用可解析 | 所有跨文档引用含路径与版本，禁用"见上文"式缩略引用 | 引用路径核验 |
| 自包含性 | 文档独立可读，不依赖会话上下文化解关键定义 | 抽样测试 |

### 4.2 代码类输出

| 维度 | 要求 | 检查方法 |
|------|------|----------|
| 编译通过 | 提交的代码必须通过类型检查 | `tsc --noEmit` / `pnpm build` |
| 测试通过 | 新增代码含对应测试且全部通过 | `pnpm test` |
| 规范符合性 | 遵循项目 ESLint/Prettier 规则 | `pnpm lint` |
| 命名一致性 | 与代码库现有约定一致 | 代码评审 |
| 无 AI 幻觉 | 不存在虚构 API、虚构配置、凭空类型 | 见 `_common/code-review-checklist.md` |
| 注释合理 | 关键约束有注释，无误导性注释 | 代码评审 |

### 4.3 决策类输出（ADR / 技术选型）

| 维度 | 要求 |
|------|------|
| 依据说明 | 每项决策给出"为什么这样选" |
| 可选方案 | 至少 2 个备选方案并说明未选原因 |
| 风险与可逆性 | 标注风险、缓解措施、可逆性（高/中/低） |
| 影响范围 | 明确波及的模块与下游 |

## 6 子代理任务单模板

### 6.1 单 agent 调用（8 项上下文）

| # | 上下文项 | 是否必填 |
|:-:|----------|:--------:|
| 1 | 业务背景 | 是 |
| 2 | 任务目标 | 是 |
| 3 | 技术约束 | 是 |
| 4 | 依赖关系 | 是 |
| 5 | 验收标准 | 是 |
| 6 | 参考资料 | 推荐 |
| 7 | 当前进度 | 推荐 |
| 8 | 相关决策 | 推荐 |

```markdown
## 子代理任务单
**任务 ID**: {TASK-YYYYMMDD-NNN}
**任务名称**: {任务名称}
**目标智能体**: {dsh-*}
**优先级**: P0 / P1 / P2 / P3

### 上下文信息（8 项）
- **业务背景**: {...}
- **任务目标**: {...}
- **技术约束**: {...}
- **依赖关系**: {...}
- **参考资料**: {...}
- **当前进度**: {...}
- **相关决策**: {...}

### 备注
{其他说明}
```

### 6.2 多 agent 并行

- 无依赖的子任务在**同一条消息**中发起多个 task 调用
- 各任务必须相互独立，无文件写入冲突
- 每个 task 独立声明 8 项上下文（无共享隐含上下文）
- 主 Agent 等待全部返回后汇总

### 6.3 多 agent 串行

- 前置任务输出作为后续任务输入时串行执行
- 前置任务输出必须做格式与关键字段验证
- 后续任务"依赖关系"项必须引用前置任务产出物路径

### 6.4 超时 / 重试 / 降级

| 维度 | 默认值 | 降级策略 |
|------|--------|----------|
| 超时 | 600 秒 | 超时 → 取消 + 输出超时报告 |
| 重试 | 1 次（仅可重试错误） | 重试仍失败 → 升级主 Agent 决策 |
| 输入不完整 | — | 阻塞，不启动子代理 |

## 7 任务规模识别

### 7.1 规模分类

| 规模 | 涉及文件数 | 涉及模块数 | 复杂度 | 风险 |
|------|:---:|:---:|------|------|
| 小规模 | ≤ 3 | 1 | 单一功能点 | 低 |
| 中规模 | 4-10 | 2-3 | 多模块功能 | 中 |
| 大规模 | 11-30 | 4-6 | 跨子系统（壳+插件+CI） | 高 |
| 超大规模 | > 30 | > 6 | 架构级改造 | 极高 |

### 7.2 处理策略

| 规模 | 处理方式 |
|------|----------|
| 小规模 | 直接执行，无需子代理 |
| 中规模 | 分解为 2-5 个子任务，顺序执行，设置检查点 |
| 大规模 | 创建子代理，分阶段执行（串行+并行），制定依赖关系图 |
| 超大规模 | 分多期执行，每期独立设计文档与验收 |

### 7.3 任务分解原则

- **粒度**：单任务 2-16 小时为宜，过大继续拆分，过小合并
- **MECE**：子任务相互独立、完全穷尽，无遗漏无重叠
- **验收独立**：每个子任务有独立验收标准
- **依赖显式**：明确标注串行依赖与可并行关系，派发前做依赖环检测
- **任务描述** ≤ 200 字，实现细节放技术约束/参考资料

## 8 会话记录规范

### 8.1 路径

```
.sessions/dsh-{角色}/{YYYY-MM-DD}/{task}.md
```

### 8.2 模板

```markdown
# 会话记录 - {任务名称}

## 元信息
- **任务 ID**: {TASK-YYYYMMDD-NNN}
- **会话时间**: {YYYY-MM-DD HH:mm:ss}
- **智能体**: {dsh-*}
- **会话状态**: {进行中/已完成/已暂停}

## 任务概述
{背景、目标和范围}

## 关键决策
| 决策点 | 决策内容 | 决策原因 |
|--------|----------|----------|

## 执行情况
- **整体进度**: {百分比}
- **已完成 / 进行中 / 待开始**: {...}

## 问题与风险
| 问题/风险 | 影响 | 应对措施 | 状态 |
|-----------|------|----------|------|

## 下一步计划
| 任务 | 计划完成 |
|------|----------|
```

> 会话记录由 harness 或 agent 在任务节点写入本地文件；跨会话恢复上下文优先读取最近一次会话记录。

## 9 技能定义模板（预留）

后续引入独立技能（skill）时，统一使用以下 frontmatter：

```yaml
---
name: "{skill-id}"                 # 格式 skill-{动词}-{对象}
description: "一句话功能描述，≤ 80 字"
metadata:
  author: "dsh-workbench"
  version: "1.0.0"
---
```

正文骨架：角色定义 → 核心原则 → 触发条件 → 输入要求 → 执行流程 → 输出规范 → 质量门禁。

## 10 评审报告模板

```markdown
---
review-target: "{被评审对象：PR #N / 设计文档路径}"
reviewer-agent: "{dsh-*}"
review-date: "{YYYY-MM-DD}"
review-round: {轮次}
---

# {对象} 评审报告

## 1 评审声明
{评审独立完成；未依赖作者自检结论替代重审}

## 2 评审总览
- 缺陷统计：P0 xN / P1 xN / P2 xN / P3 xN
- 评审结论：通过 / 有条件通过 / 不通过

## 3 缺陷清单
{每条 P0/P1 缺陷含：编号、等级、文件与行号/章节引用（≤50 字摘录）、问题描述、对下游影响、整改建议}

## 4 整改建议汇总
{按优先级排列}
```

缺陷等级与结论判定标准见 `_common/review-foundation.md`。
