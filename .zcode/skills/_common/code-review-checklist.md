# 代码评审检查清单

> **适用范围**: PR 代码评审、交叉评审
> **定位**: 定义全面的评审检查项，含 AI 生成代码专项幻觉检查。

---

## 1 架构与模块检查

- [ ] 模块边界是否清晰，是否存在跨层越权调用（Electron：main/renderer 职责是否越界）
- [ ] 是否与设计文档 / ADR 的决策一致
- [ ] 新增依赖是否必要，是否与现有依赖重复
- [ ] IPC 通道命名与负载设计是否与既有约定一致

## 2 TypeScript 编码规范检查

- [ ] 命名规范（类型/组件 PascalCase，变量/函数 camelCase，常量 UPPER_SNAKE_CASE）
- [ ] 无 `any` 滥用；公共 API 有显式类型定义
- [ ] 关键逻辑有注释（说明约束而非复述代码）
- [ ] 组件 Props 使用 Interface 定义；未使用的导入/变量已清理

## 3 Electron / 桌面壳专项检查

- [ ] 渲染进程开启上下文隔离（contextIsolation），无 nodeIntegration 泄漏
- [ ] IPC 调用有输入校验；特权接口不暴露给不可信内容
- [ ] 子进程（dsh Node 进程）有生命周期管理：退出清理、崩溃重启、端口冲突处理
- [ ] 敏感信息（API key、token）不硬编码、不写入日志
- [ ] 跨平台兼容（路径分隔符、大小写敏感文件系统、平台专属 API 有守卫）

## 4 Cordis 插件专项检查

- [ ] 插件副作用可逆：定时器/监听器通过 `ctx.effect()` 注册，卸载时自动清理
- [ ] 服务依赖通过 `inject` 显式声明，不隐式依赖加载顺序
- [ ] 打包配置正确：react 与 `@deepseek-ai/*` 保持 external
- [ ] 插件加载/卸载/热重载不破坏宿主状态

## 5 测试与性能检查

- [ ] 新增功能有对应测试（Vitest 单测 / Playwright E2E）
- [ ] 无明显性能隐患（主进程阻塞、渲染层大列表无虚拟化、重复构建）
- [ ] 输入参数有校验；错误路径有处理

## 6 AI 生成代码专项幻觉检查

### 6.1 API 虚构
- [ ] 调用的 API/IPC 通道/Electron 接口真实存在（对照 @deepseek-ai/* 与 electron 的实际类型定义）
- [ ] Cordis ctx 上的服务与事件真实存在，非凭空编造

### 6.2 配置虚构
- [ ] 代码引用的配置项/环境变量有对应定义与文档

### 6.3 类型凭空
- [ ] 引用的类型/接口已定义或来自真实依赖

### 6.4 注释误导
- [ ] 注释描述与实际代码逻辑一致（防"注释说一套、代码做一套"）

### 6.5 测试造假
- [ ] 测试断言真实有效（非恒真断言、非 mock 掉被测逻辑本身）

## 7 问题分级标准

| 级别 | 代号 | 定义 | 处理要求 |
|------|:----:|------|---------|
| 严重 | P0 | 架构缺陷、安全漏洞、数据丢失风险 | 必须修复，阻塞合并 |
| 一般 | P1 | 设计缺陷、规范违反、潜在风险 | 应该修复 |
| 建议 | P2 | 优化建议、代码风格、文档完善 | 建议修复 |

P0/P1 缺陷必须举证：文件+行号引用、问题描述、对下游影响，缺一不可（见 `_common/review-foundation.md` 举证义务）。
