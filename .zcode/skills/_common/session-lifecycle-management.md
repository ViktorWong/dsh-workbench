# 会话生命周期管理规范

> **适用范围**: 所有智能体
> **定位**: 定义跨阶段的会话复用/新建策略、上下文预算控制与释放机制。

---

## 1 会话状态分级

| 级别 | 上下文使用率 | 状态说明 | 行动 |
|:----:|:--------:|---------|------|
| **fresh** | < 30% | 上下文充裕 | 可复用当前会话 |
| **moderate** | 30-60% | 可继续但需裁剪输入 | 复用，执行上下文裁剪 |
| **high** | 60-80% | 紧张，仅可加载小任务 | 评估是否新建会话 |
| **critical** | > 80% | 质量下降风险高 | 必须新建会话 |

> 上下文使用率 = 已消耗 token / 模型上下文窗口上限（近似估算）

## 2 跨阶段衔接策略

| 阶段转换 | 推荐策略 | 原因 |
|---------|:------:|------|
| issue 分诊 → 方案设计 | 同会话 | 需求上下文高度重叠 |
| 方案设计 → 编码 | **新建会话** | 上下文从设计文档切换到源代码 |
| 编码 → 单元测试补充 | 同会话 | 源码上下文可复用 |
| 编码/设计 → **评审** | **新建会话** | 评审需要全新视角，避免确认偏误 |
| 评审 → 缺陷修复 | **新建会话** | 修复聚焦代码上下文 |
| 缺陷修复 → 回归验证 | 同会话（增量） | 需引用修复内容 |
| 打包发布 | **新建会话** | 发布需要独立、干净的环境上下文 |

## 3 强制新建会话条件

- 上下文达到 critical（> 80%）
- 上下文类型根本性切换（设计 → 编码、编码 → 评审、编码 → 发布）
- 上一阶段检出 ≥ 2 次 AI 幻觉（虚构 API/类型），当前会话质量已不可信
- 会话已连续执行 ≥ 3 个阶段

## 4 上下文释放清单

每阶段完成后释放：

| 阶段完成后 | 释放内容 |
|-----------|---------|
| 方案设计 | 上游文档全文（仅保留设计文档本身） |
| 编码 | 设计文档全文（仅保留 API/接口约定摘要）、已完成任务的源码全文 |
| 评审 | 源代码全文（仅保留评审报告） |
| 测试 | 测试执行原始日志（仅保留结果摘要与覆盖率摘要） |

## 5 调度决策流程

```
调度下一阶段
  ├─ critical（>80%）→ 强制新建会话
  ├─ high（60-80%）
  │    ├─ 上下文类型切换？→ 是 → 强制新建
  │    └─ 否 → 可释放 ≥30% 上下文？→ 是 → 释放后复用 / 否 → 新建
  ├─ moderate（30-60%）→ 按 §2 推荐衔接
  └─ fresh（<30%）→ 复用
```

## 6 异常场景处理

| 异常场景 | 处理方式 |
|---------|---------|
| 检测到 AI 幻觉（≥2 次虚构 API/类型） | 终止当前会话，新建会话重新执行当前阶段 |
| 会话中断（超时/错误） | 新建会话继续未完成阶段，读取最近会话记录恢复进度 |
| 用户手动介入后返回 | fresh/moderate → 继续复用；high/critical → 新建 |
