# 输出路径与命名规范

> **适用范围**: 所有智能体的文档与报告产出
> **定位**: 定义标准输出路径、文件命名与版本规则。

---

## 1 设计文档命名

```
docs/design/{主题}-{YYYYMMDD}-v{版本号}.md
```

示例：
- `docs/design/desktop-shell-architecture-20260826-v1.md`
- `docs/design/plugin-lifecycle-20260901-v1.md`
- ADR：`docs/design/adr/{序号}-{主题}.md`，如 `docs/design/adr/001-electron-vs-tauri.md`

## 2 会话记录路径

```
.sessions/dsh-{角色}/{YYYY-MM-DD}/{task}.md
```

## 3 评审报告路径

- 用户指定优先
- 默认：与被评审文档同目录的 `review/` 子目录，命名 `{被评审文件名}-review-report.md`
- PR 代码评审：结论直接写入 PR 评论/会话记录，不单独落盘

## 4 版本号规则

| 变更类型 | 版本动作 |
|---------|---------|
| 评审修订（接受/部分接受意见） | minor +1（v1.0 → v1.1），**保留旧版文件，禁止覆盖** |
| 结构性变更（推翻决策、章节重构） | major +1（v1.x → v2.0） |
| 文字/格式修正（无实质变更） | 同版本内原地修正 |

- 豁免条款：报告类、会话记录、临时草稿允许原地修订，不适用版本累加
- 判定准则：该文档是否为"下游交付物"（被后续环节消费）。是 → 严格执行累加；否 → 豁免

## 5 路径验证规则

- 启动子任务前，必须验证任务输入中所有文件路径存在
- 路径不存在时报告错误（含缺失路径与期望位置），不得静默继续

## 6 文档目录（TOC）规范

- 一级章节 > 5 个的文档必须含 `## 目录` 章节，位置在元信息块之后、正文第 1 章之前
- 目录由正文标题树推导生成（可执行 `grep -n '^#' {文档}` 后组装），禁止凭记忆手写锚点
- 修订导致章节变化时必须同步刷新目录；目录与正文不一致视为 P2 缺陷
